第1回 gitとhtml

第1回の授業では、gitでファイルを管理してWebに公開する方法と、htmlでページを書く方法を学びました。このページは、その内容を後から読み返してもわかるようにまとめたものです。

gitに関して

gitとは

gitは、ファイルの変更履歴を記録する「バージョン管理システム」です。いつ、どのファイルを、どう変えたかを記録しておけます。

gitを使わない場合、「レポート_最新.docx」「レポート_最新2.docx」のようにファイルをコピーして残すことになり、どれが本当の最新なのかわからなくなります。gitを使うと、ファイルは1つのままで、次のことができます。

  • 過去の状態にいつでも戻せる
  • どこを変えたのかを後から確認できる
  • 複数人で同じファイルを編集しても、変更をまとめられる

gitとGitHubの違い

名前が似ていますが、別のものです。

  • git：自分のパソコンの中で動く、履歴を記録するための道具
  • GitHub：gitで記録した履歴をインターネット上に置いておけるサービス

gitだけでも履歴の管理はできますが、パソコンが壊れると履歴も消えてしまいます。GitHubに置いておくと、バックアップになり、他の人と共有したり、Webページとして公開したりできます。

用語

  • リポジトリ：ファイルとその変更履歴をまとめて保存している場所。自分のパソコンにあるものを「ローカルリポジトリ」、GitHubにあるものを「リモートリポジトリ」と呼ぶ。
  • ステージング（add）：次のコミットに含めるファイルを選ぶこと。変更したファイルのうち、記録したいものだけを選べる。
  • コミット（commit）：選んだ変更を、メッセージをつけて履歴に記録すること。ゲームのセーブポイントのようなもの。
  • プッシュ（push）：ローカルリポジトリのコミットを、リモートリポジトリ（GitHub）に送ること。
  • プル（pull）：リモートリポジトリの新しい変更を、自分のパソコンに取り込むこと。
  • クローン（clone）：リモートリポジトリを丸ごと自分のパソコンにコピーすること。最初の1回だけ行う。

ファイルを公開するまでの手順

ファイルを編集してから公開するまでの流れは、次の3ステップです。

  1. add：記録したいファイルを選ぶ
    git add ファイル名（全部まとめて選ぶときは git add .）
  2. commit：選んだ変更をメッセージつきで記録する
    git commit -m "何を変えたかのメッセージ"
  3. push：記録した内容をGitHubに送る
    git push

今どのファイルが変更されているかは git status で確認できます。

大事なのは、commitしただけではGitHubには反映されないことです。commitは自分のパソコンの中での記録で、pushして初めてインターネット上に送られます。

コミットメッセージ

コミットにつけるメッセージは、後から履歴を見たときに「このとき何をしたのか」を知る手がかりになります。「更新」だけでは内容がわからないので、「第1回の演習ノートを追加」のように、何を変えたのかを書くと後で役に立ちます。

GitHub Pagesで公開される仕組み

GitHub Pagesは、GitHubのリポジトリに入っているhtmlファイルを、そのままWebページとして公開してくれる機能です。pushすると、少し時間をおいて公開ページにも反映されます。

公開されるURLは、次の形になります。

https://ユーザー名.github.io/リポジトリ名/フォルダ名/ファイル名

リポジトリの中のフォルダ構成が、そのままURLになります。たとえば、リポジトリの中の「de12」フォルダにある「1.html」は、URLの最後が /de12/1.html になります。

ホームページとhtmlファイルの関係

ふだん見ているホームページの正体は、webサーバーに置いてあるhtmlファイルです。ブラウザはそのファイルを受け取って表示しています。

つまり、自分のホームページを作る手順は次の2つだけです。

  1. htmlファイルを自分で書く
  2. webサーバーにアップロードする

この授業では、webサーバーとして無料のGitHub Pagesを使います。gitでpushすることが「アップロード」にあたります。

htmlという名前の意味

htmlは「Hyper Text Markup Language」の略です。2つに分けて覚えます。

  • Hyper Text：「テキストを超えた文書」という意味。テッド・ネルソンが提唱した考え方で、著書『Computer Lib』で紹介されている。文字だけでなく、他のページへのリンク、画像、動画などがつながった文書のこと。
  • Markup：文書の中に「意味」をつけていくこと。「ここは見出し」「ここは画像」という印をつける。

その印が「タグ」です。htmlを書くというのは、文章にタグで意味をつけていく作業だと考えるとわかりやすいです。

タグの書き方

タグは < と > で囲んで書きます。開始タグと終了タグで文字をはさむのが基本で、終了タグには / がつきます。

<h1>見出し1</h1>

こう書くと、文字が「見出し」という意味を持ち、見出しらしい大きさで表示されます。自分で文字の大きさを指定しているのではなく、意味をつけた結果として大きくなる、という順番です。

  • <h1>：大見出し
  • <h2>：中見出し
  • <h3>：小見出し

タグの中に書く src="..." や href="..." のような追加の情報は「属性」と呼びます。

headとbody

htmlファイルは、headとbodyの2つの部分に分かれています。

  • <head>：ページの設定を書く場所。タイトルや、読み込むスタイルシートを書く。
  • <body>：画面に表示される中身を書く場所。文章や画像はここに書く。

迷ったら「見せたいものはbody、設定はhead」と覚えておきます。

フォルダの構成とファイル名のルール

ブートキャンプで、ホームディレクトリの中に「mygit」フォルダ、その中に「xbp」フォルダを作りました。デザイン演習Ⅰ・Ⅱでは、xbpの中の「de12」フォルダを編集していきます。

ホームディレクトリ
  └ mygit
      └ xbp
          └ de12   ← ここを編集する

覚えておくルールは2つあります。

  • トップページは index.html：URLをフォルダまでしか書かなかった場合、ブラウザはそのフォルダの中のindex.htmlを表示する。だから各フォルダの入り口になるページはindex.htmlという名前にする。
  • ファイル名は半角英数字：日本語のファイル名は不具合の原因になるので使わない。画像ファイルも同じ。

書いた結果を確認する（Live Server）

VSCodeの拡張機能「Live Server」を使うと、編集中のhtmlファイルをブラウザで表示できます。ファイルを保存するたびに表示が更新されるので、書く → 保存 → 確認、を繰り返して進めます。

文字を書く：divとbr

文章は、段落などのかたまりごとに <div> タグでくくります。divは「division（分割）」の略です。

htmlでは、ファイルの中で改行しても画面では改行されません。改行したい場所には <br> タグを書きます。

<div>
    ああああああ<br>
    12345678<br>
    いいいいいい
</div>

画像を入れる：img

画像の表示には <img> タグを使います（imageの略）。終了タグはいりません。

<img src="./images/testimage.png" width="30%">

  • src：画像ファイルの場所を書く。sourceの略。
  • width：画像の幅。% で書くと、画面の幅に対する割合になる。width="30%" なら画面の幅の30%。

写真を載せるときの注意：スマホやデジカメの写真は印刷用に解像度が高く、ファイルサイズがとても大きいです。ホームページではそこまでの大きさは必要なく、大きいと表示が遅くなります。GitHubにpushする写真は、1MB（1024KB）以下に小さくしてから入れます。

ファイルの場所の書き方（階層）

画像やリンク先の場所は、今編集しているファイルから見た位置で書きます。使う記号は2つです。

  • ./：同じ階層（今のファイルと同じフォルダ）
  • ../：1つ上の階層

読み方のコツは、/ を「中の」と読み替えることです。

./images/testimage.png → 「同じ階層の〈中の〉imagesフォルダの〈中の〉testimage.png」

de12フォルダの中にあるファイルから見た場合の例です。

  • ./images：de12の中のimagesフォルダ
  • ../images：1つ上のxbpフォルダの中のimagesフォルダ（de12と同じ階層にある別のimagesフォルダ）
  • ../index.html：xbpフォルダの中のindex.html（XBPのトップページ）

この書き方は画像だけでなく、リンクやスタイルシートなど、ファイルを指定する場面すべてで共通です。VSCodeでは ./ や ../ と入力するとフォルダやファイルの候補が出るので、そこから選ぶと打ち間違いを防げます。

箇条書き：ol、ul、li

  • <ol>：番号つきの箇条書き。ordered listの略。
  • <ul>：番号なしの箇条書き。unordered listの略。
  • <li>：箇条書きの1項目。listの略。olかulの中に書く。
<ol>
    <li>ああああああ</li>
    <li>いいいいいい</li>
</ol>

番号をなくしたいときは、ol を ul に変えるだけです。略す前の英語（ordered＝順番あり、unordered＝順番なし）で覚えると混ざりません。

リンクを作る：a

リンクには <a> タグを使います（anchorの略）。

  • href：リンク先を書く。hypertext referenceの略。
  • target="_blank"：リンク先を新しいタブで開く。書かなければ同じタブで開く。
<a href="./index.html">デザイン演習Ⅰ・Ⅱトップページ</a>
<a href="../index.html">XBPトップページ</a>
<a href="https://www.yahoo.co.jp/" target="_blank">Yahoo</a>
<a href="./files/test.pdf" target="_blank">pdfファイル</a>

リンク先の書き方は3種類あります。

  • 自分のサイトの中のページ：./ や ../ を使って場所を書く
  • 外部のサイト：https:// から始まるURLをそのまま書く
  • pdfなどのファイル：ページと同じように場所を書けば、そのファイルが開く

タイトルを変える：title

headの中の <title> タグに書いた文字が、ブラウザのタブに表示されます。ページの本文には出てきません。

<title>XBPのページ</title>

スタイルシートを読み込む：css

cssファイルは、htmlのいろいろな書式（背景、余白、文字の大きさなど）をまとめて決めておくファイルです。読み込むだけで、タグごとの書式がページに反映されます。

headの中に次のように書きます。

<link rel="stylesheet" href="./css/style.css">

うまく読み込めると、背景や右側の余白が整います。見た目が変わらないときは、href の場所の書き方が合っているかを最初に確認します。

公開するときに守ること

ホームページは誰でも見られる場所に公開されるので、次のことを守ります。

  • 個人情報（住所、学籍番号など）を載せない
  • 本人の許可がない顔写真や氏名を載せない
  • 誹謗中傷にあたる内容を載せない
  • 引用するときは、引用元を明らかにする
  • 外部のページにリンクを貼るときは、自分のページではないことを明記する（明記しないと、自分が作ったページのように見えてしまう）
  • 動画ファイルは絶対にGitHubにpushしない。ファイルが重く、最悪の場合リポジトリが壊れる。動画を見せたいときはYouTubeにアップロードして、リンクを貼るか、埋め込み用のコードをhtmlに貼りつける。

情報の公開は、神奈川大学の情報倫理に関するガイドラインに沿って行います。

早見表

書き方を忘れたときは、まずここを見ます。

  • 見出し：<h1> <h2> <h3>
  • かたまり：<div>（division）
  • 改行：<br>
  • 画像：<img src="場所" width="30%">
  • 番号つき箇条書き：<ol> と <li>
  • 番号なし箇条書き：<ul> と <li>
  • リンク：<a href="場所">文字</a>
  • タイトル：<title>（headの中）
  • スタイルシート：<link rel="stylesheet" href="場所">（headの中）

疑問に思って調べたこと

imgのaltは何のためにあるのか

alt は、画像の内容を文字で説明するための属性です。画像が読み込めなかったときに代わりに表示されます。また、目の不自由な人が使う読み上げソフトは、この文章を読み上げます。画像が見えない人にも内容が伝わるように書きます。

lang="jp" と lang="ja" はどちらが正しいのか

正しいのは lang="ja" です。lang 属性には言語を表すコードを書きます。「ja」は日本語という言語のコードで、「jp」は日本という国のコードなので、言語の指定には使えません。

meta charset="UTF-8" は何のためにあるのか

ファイルの文字コード（文字をどういう決まりで保存しているか）をブラウザに伝えるためのものです。これがないと、ブラウザが文字コードを間違えて、日本語が文字化けすることがあります。headの中のなるべく上のほうに書きます。

タグを画面にそのまま表示するにはどうするのか

このページのようにタグの説明を書きたいとき、<h1> とそのまま書くと、ブラウザがタグとして処理してしまい、文字として表示されません。< は &lt;、> は &gt; と書くと、記号として表示されます。
